# I Started Coding as a Hobby. GSoC Taught Me to Think Like an Engineer.

I started coding the way most people do  tutorials, small projects, the dopamine hit of making something work. It was fun, but it was isolated. I was writing code for myself, about problems I invented.

## The Open Source Shift

Contributing to open source changed everything. Suddenly, the code had *users*. It had a history. It had conventions I didn't create but had to respect. My first PRs were clumsy  I'd solve the problem but break the style. I'd add a feature but miss the edge case that the maintainer caught in review.

That friction was the education.

## What GSoC Taught Me

Google Summer of Code with CHAOSS (Linux Foundation) was the turning point:

- **Systems thinking**: I stopped seeing individual functions and started seeing data pipelines. How does this metric flow from raw data to a dashboard? What breaks when the data shape changes?
- **Communication as engineering**: Writing a good issue description, a clear PR summary, a design doc  these aren't overhead. They're engineering artifacts.
- **Quality over quantity**: My mentor didn't care how many lines I wrote. They cared whether I understood the problem deeply enough to solve it simply.

## The Before and After

Before GSoC, I asked: *"How do I build this?"*
After GSoC, I started asking: *"Why does this need to exist? What problem does it solve? Who benefits?"*

That shift  from implementation to intention  is what separates coding from engineering.
